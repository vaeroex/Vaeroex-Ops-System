The scheduler is bounded to 50 attempted connections per tick in five batches of 10. All connections share a 240-second work deadline, propagated through provider transport/body reads, token refresh, and database requests. Cleanup and backoff use a fresh signal with a 285-second cutoff inside the 300-second route limit. Commit requests allow up to 120 seconds capped by remaining work time. A submitted atomic commit can have an uncertain acknowledgement; its completed run remains authoritative, and cleanup cannot overwrite it. These bounds can defer due connections to a later tick; the browser tests do not prove a live refresh service-level guarantee.
