# Local shared-answer contract v2

The current local date/selection correction is described in
[Cross-source selection and date comparison](vsi-cross-source-date-contract.md).
Cross-original `missing_information` uses a closed, application-computed date
assessment across all selected business observations; free text in that field is limited to one
business original. Specific multi-source evidence questions remain proposed
`next_checks`. The historical qualification receipts below are not receipts for
this latest local candidate.

This candidate is inactive. It does not authorize publication, deployment,
credentials, inference, SQL changes or activation. Existing three gates remain
false. The general/public answer contract remains available when no stored
business evidence is used; an explicit stored-data question cannot silently
fall back to that route. Shared clarifications are labeled drafts and use the
same plain, nonnumeric output protocol as shared narrative.

For an admitted shared-business answer the provider returns `observations`,
`results`, `hypotheses`, `missing_information` and `next_checks`. It cannot return
free-form factual `content` or its own citation list. An observation selects a
source reference, exact immutable binding and fact index. The app renders the
complete issued fact, original values/dates/units, source attribution and
canonical citation. Each requested protected provider/connection/entity scope
must be represented by at least one selected observation. Multiple rows from
that same scope are available context, not a requirement to recite every row.
Other packed originals remain optional unless used by a claim or issued result.
Explicit invoice-focused questions restrict Xero observations to issued typed
sales-invoice fact indexes, with valid zero invoices preserved. Advisory invoice
review order is not period alignment, a record join or completeness proof.
Ambiguous tied scopes stay distinct requirements; the model cannot substitute
an unrelated connection simply because its provider name matches. Packing
dependency joins do not merge coverage requirements across providers/scopes.
Scope qualifiers also come from the prepared source, not model prose. URLs inside
quoted records get an explicit original-citation marker; their immutable source
text remains intact and they are not promoted to verified external answer links.
Results select exact application-issued result IDs with all current input
bindings. This adds no arithmetic recipe or labor/inventory authority.

The transport includes application-owned `answerSourceRequirements.groups` of
valid source references. The renderer enforces the same groups independently of
model prose. Every selected fact still needs its exact binding/index, every
draft premise must be an observed fact, and an issued calculation needs all its
observed input bindings. Omitting optional context never licenses an invented
total, trend, causal relationship or exhaustive-review claim. The UI marks a
selective answer partial even when all available originals fit in the input.
Coverage failures log bounded counts only, not source IDs, hashes, facts or
rejected prose. The synthetic hosted-shape regression preserves fifteen sealed
originals, seven in model context and two cited observations across the two
required scopes. It also checks both possible row selections, wrong-connection
substitution, missing sources, calculation dependencies and access revocation.
This reproduces a contract failure shape, not the discarded live answer.

Drafts reference visible observations. Hypotheses additionally require two
independent business originals and the existing hypothesis gate. Product and
completed public-lookup context can be selected through the same bound fact
protocol, but cannot become independent business corroboration. Historical
assistant claims are not promoted into new facts. Source and result selection
does not change protected admission, current eligibility, actor/workspace/session
checks, provider routing, manifest settlement, usage accounting or citation
reopening.

There is no business-word whitelist or English causal-word classifier. Ordinary
questions, negations and new phrasing are allowed. Every authored narrative item
is displayed as an unverified hypothesis, model assessment or suggested check,
never as an independently verified finding or completed action. Values and dates
belong in app-rendered observations/results rather than numeric literals in draft
prose. The provider schema and runtime both enforce this representation rule;
runtime additionally rejects Unicode numeric characters, controls, inline citation
markup, HTML, URLs and credential-shaped strings. Text is escaped for display.
The original answer-length and thirty-citation bounds remain in force; canonical
source data is never silently shortened to make an output pass.

Reference, version, dependency and schema checks are deterministic. Natural
language entailment, truthful attribution inside draft prose, causation, relevance
and usefulness are not. A false insinuation or spelled-out quantitative claim can
still be emitted as explicitly unverified prose. It must fail honest manual
grounding/usefulness review; these tests do not claim semantic verification.
The retained generic evaluation answer is a mechanical-format example, not a
usefulness pass. Useful compatible and sparse fixture answers need no forced
hypothesis: specific cited missing-information checks are valid outcomes.

Local checks use synthetic sources and mocked providers. Save/reopen checks use
the existing disposable PGlite fixture with screened captures kept outside Git;
they are not new native concurrency or hosted-database qualification. Real-model
schema compliance, answer quality and production acceptance remain unverified.

## Replacement coverage and local qualification

The four removed public qualitative suites tested the superseded free-text/word-filter
protocol. Their protections are exercised through the new protocol rather than
through renamed success assertions:

| Boundary | Replacement coverage |
| --- | --- |
| Exact premises, attribution and independence | Issued ref/binding/fact-index selection; provider and quote overrides denied; duplicate premises and shared dependency roots denied; distinct facts retain original citation identity. |
| Factual and calculation authority | Free-form factual content denied; invented/tampered result IDs and missing inputs denied; facts, values, dates, scope and attribution rendered by the application. |
| Eligibility, privacy and persistence | Actual engine scenarios reject wrong workspace, cross-case facts, revocation and a closed stored-data plan; mixed public research excludes private context; local database cases check save/reopen and wrong-actor/workspace/revoked-source denial. |
| Natural prose and display | Questions and negations are allowed as labeled drafts; the actual UI renderer retains those labels. Numeric literals, model URLs, markup and credential-shaped prose remain rejected. Quoted original URLs remain in the protected original, with an explicit display marker. |
| Semantic limits | False causal, quantitative or attribution insinuations can mechanically pass only as labeled drafts. They are explicit negative manual-review examples, not automatically detected semantic failures. The retained generic answer remains a recorded usefulness failure. |

The earlier contract qualification used runtime `c6ce9d7e6c161162cb53677cc642eea928ed5a29`.
The source-coverage correction is pinned separately to runtime
`c185cb0e669bf7ccd94805d04243f4bd8246fc01`; its updated evaluator retains
the same two case-local synthetic datasets, request limits and manual review.
All sixteen registered VSI suites passed against that runtime, along with the
three selected five/six/twelve-plugin local save/reopen cases, consumer guards,
TypeScript and focused zero-warning ESLint. Private dummy-only transport checks
also passed locally; their helpers and private diagnostics are excluded from this
public candidate.
The final test-only additions exercise both HTTPS and `www.` quoted-source URL
presentation and confirm draft labels survive the actual UI renderer. No runtime
change followed qualification. These receipts are local mocked/disposable checks,
not a full application release build or real-model acceptance.
