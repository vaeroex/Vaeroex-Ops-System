# Owner-authenticated qualification preparation

PR #571 adds `/app/si/prepare` and `POST /api/vsi/prepare` for isolated Preview qualification. Both are absent/denied without the explicit preparation scope; Production cannot enable the scope. No migration is needed.

`VAEROEX_VSI_PREPARATION` is deployment-only JSON with exact `actorUserId`, `workspaceId`, SHA-256 `questionHash`, `startsAt`, and `expiresAt`. Maximum duration is two hours. Malformed, missing, expired, different-actor/workspace/question scopes fail closed. This variable cannot authorize model execution. Set it only on the second isolated refresh build, preserving the campaign configuration and cumulative build allowance.

The normal authenticated API checks origin, active workspace, current user/session and subscription, strict management burst rate, and independently requires current owner membership. Protected evidence RPCs run on that owner's ordinary Supabase client. A normal read ticket is opened and bound to the prepared roots. No admin source read, forged session, manual evidence construction, question reservation, chat write, model generation, or provider ingestion occurs.

The owner enters the exact approved question on the page. `prepareVsiSharedEvidence` selects the UTC discovery window and invokes `prepareSharedGeneration`; the answer engine uses that same helper. The response contains the **whole bounded prepared set**, not just sources supporting a chosen answer: identities (including source versions), hashes, provider, scope, fact dates, complete fingerprint, discovery window, coverage and limitations. Raw source prose is omitted. Normal pipeline limits (24 sources, selection/character budgets) remain and omissions are disclosed. No page/operator checksum is substituted for a protected hash.
