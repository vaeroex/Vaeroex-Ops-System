## Detailed verified findings

Proof artifacts in this section are relative to this document's directory. The core SQL harness uses a reduced schema and explicitly granted authenticated privileges. Its anonymous SELECT denial occurs at the fixture's grants boundary, which is narrower than production's anon grants; it must not be used as proof of production anonymous RLS. The fixture also grants broader authenticated workspace CRUD than production, so it does not establish full ACL parity. Grants for the specific operations underlying VXA-003–005 were confirmed live. Actual runtime parameters and remaining limitations are retained in the evidence JSON.
### VXA-001 — High — Upload parsing inflates compressed content before enforcing real output limits

**Impact:** An authenticated uploader can submit a small DOCX/PDF or forged XLSX whose expansion exhausts function memory/CPU. The 25 MiB upload cap does not bound expanded bytes. This can fail the request, disrupt concurrent work on its instance, and consume capacity. No large payload or production stress was attempted.

**Evidence:** `lib/imports/document-text.ts:40–71` expands every ZIP entry with `inflateRawSync` at line 62 and no `maxOutputLength`, cumulative cap, or ratio cap. DOCX text slicing in callers happens after extraction. PDF has the same unbounded `inflateSync`/`inflateRawSync` at lines 222/225 (static evidence only). `lib/imports/spreadsheets.ts:243–289` obtains declared uncompressed length from the untrusted central directory, checks declared size/ratio at 260–269, inflates without a runtime bound at 286, and only then checks actual length at 288. `app/app/files/actions.ts:1789,1815,1839,2917` invokes these parsers on uploaded files.

**Isolated reproduction:** `audit-evidence/stage-1/vaeroex-decompression-audit.cjs` synthesizes a 2,215-byte ZIP with 2,083 compressed bytes yielding 2,097,188 bytes. DOCX is accepted and produces 2 MiB text. Changing only XLSX central-directory uncompressed length to `1` bypasses the pre-inflate safety checks: 2,097,188 bytes allocate before the later mismatch rejection. The bounded fixture is intentionally only 2 MiB. Actual-module test passed on working and production snapshots; outputs `audit-evidence/stage-1/vaeroex-decompression-results.jsonl` and `audit-evidence/stage-1/vaeroex-decompression-production-results.jsonl`.

**Correction:** Set enforced output-length limits on every inflater, cap total expanded data and processed entries, validate ZIP structure and size consistency, and extract only needed parts. Apply equivalent PDF stream bounds; stop processing when limits are hit.

**Verification:** Forged declared sizes, excessive ratios, cumulative many-entry expansion, and compressed PDF streams reject before expanded buffers exceed the configured per-entry/total budgets; ordinary supported files still parse. Test in isolated worker with measured maximum memory and bounded fixtures.

### VXA-002 — High — Unsupported numerical claims pass the evidence-grounding gate

**Impact:** File-analysis output can be labeled verified business evidence even when its numeric claim contradicts the original text. Eligible local-extraction outputs receive `requiresReview:false`; the auto-learning branch can persist summaries and analysis metadata to Business Memory. Actual auto-learning/persisted customer output was not exercised.

**Evidence and repro:** Call actual `assessFileAnalysisEvidence` with `outputJson:{findings:['Revenue amount October 999']}`, source `Revenue amount October 100. This financial worksheet records the actual October revenue amount for the business.`, and `sourceGrounding:'local_extraction'`. Result: `eligible:true`, `classification:'business_evidence'`, `factCount:1`, `requiresReview:false`. No 999 exists in the source. The function computes numeric-support false, then falls back to three shared words; numeric mismatch is not a rejection.

**Code:** `lib/ai/evidence-index.ts:204–212` (`isClaimSupportedBySource`), `:248` supportedFacts, `:287–294` successful assessment; `app/app/files/actions.ts:1998–2014` classification, `:2070–2080` review gate, `:2134–2164` auto-learning index path; `lib/ai/evidence-index.ts:1130–1154` summary/analysis metadata persistence.

**Correction:** Require every numerical token to be grounded in the specific cited fact, preserve sign/currency/unit/period, and fail the claim when numeric support is absent. Word overlap alone should not establish factual support. Distinguish source text eligibility from verification of model assertions and prevent unsupported claims from being accepted through one unrelated supported fact.

**Verification:** Source 100/claim 999 must be ineligible or require explicit review, including signed values, percent/fraction, currency, small numbers, swapped metric labels, wrong periods and reversed direction. Supported 100 must continue to pass. Use synthetic output through the complete approved-persistence path and verify unsupported summaries never become trusted memory.

### VXA-003 — Medium — Subscription denial does not apply to direct workspace database access

**Impact:** A member whose paid entitlement expires can continue permitted CRUD via Supabase Data API/SQL using their valid authenticated session, bypassing the application's paid-access gate. This is a paywall/business-rule bypass, not cross-tenant disclosure. A product decision is needed on read-only access after expiry, but mutations currently bypass the implemented application rule.

**Evidence:** `supabase/migrations/202606170001_phase_1_schema_rls.sql:335–395` membership/role helpers consult active membership only. `20260819174100_security_high_findings_remediation.sql:8–28` contributor helper likewise ignores entitlement. Current KPI contributor policy at 235–240 and `202606180002_kpi_dashboard.sql:37–58` retain grants and policies independent of subscription. Read-only live catalog inspection confirmed active helpers/policies have no billing predicates. App contrast: `lib/security/require-workspace-access.ts:7–17` calls `requireActiveSubscription`.

**Isolated reproduction:** `audit-evidence/stage-1/vaeroex-core-rls-audit.cjs` creates canceled, subscription-required Workspace A without entitlement and an owner role, applies actual current policies, sets the authenticated role, then inserts a KPI in A successfully (one persisted row). Cross-tenant read/write tests fail as intended, demonstrating this is entitlement rather than tenant failure. Result in `audit-evidence/stage-1/vaeroex-core-rls-results.json`.

**Correction:** Define which operations remain allowed after expiry. Enforce mutation entitlement in trusted DB predicates/RPCs or remove direct client mutation grants and require scoped server paths. Preserve account/billing recovery and deliberate read-only/export policy.

**Verification:** Isolated real account with active, expired, canceled, manually activated, trial and no-subscription-required states exercises both app endpoints and direct Data API; denied mutations create no rows. Match Stripe precedence/freshness and recovery policies.

### VXA-004 — Medium — Contributors can forge another user's security events and trigger their tool lockout

**Impact:** A staff member can corrupt the security audit trail and deny an owner/manager the mutation operations behind `requireToolExecution`. They can insert 12 false blocked events attributed to the victim, meeting the default 10-minute lockout threshold. Forged timestamps can also extend misleading event history. No evidence of existing malicious events was sought or found.

**Evidence:** `202607080002_ai_tool_execution_security.sql:1–56` permits authenticated INSERT with caller-supplied `user_id`, `allowed`, `created_at`, and operation metadata. The active replacement `20260819174100_security_high_findings_remediation.sql:256–263` checks only own-workspace contributor role. `lib/security/tool-execution-gateway.ts:382–400` counts `allowed=false` rows for target user in the last 10 minutes, and lines 424–433 block tools at threshold (default 12 at 152).

**Isolated reproduction:** Actual-policy PGlite harness signs in as synthetic Staff A and inserts 12 rows with Workspace A plus Owner A's user ID using INSERT without RETURNING (staff cannot SELECT security events). Owner A's query then sees 12 blocked events. Source consumer deterministically denies the tool operation at that threshold. Both assertions recorded in `audit-evidence/stage-1/vaeroex-core-rls-results.json`. Production policy and authenticated INSERT grant were confirmed by read-only catalog inspection; see production-audit-event-catalog.json.

**Correction:** Record trusted security decisions through server-only logging/RPC authority; derive actor and timestamp, don't allow clients to assert audit outcomes or another actor. At minimum actor binding helps but does not establish event authenticity. Base lockout on trusted, atomic counters, not user-writable audit data.

**Verification:** Staff/manager direct inserts forging actor/outcome/time are denied; authenticated server decisions are stored; true blocked operations enforce intended limits without another contributor being able to lock out the victim.

### VXA-005 — Medium — Asset checks accept foreign-tenant asset references

**Impact:** Tenant A can persist an asset check referring to an asset owned by Tenant B when B's asset UUID is known. It corrupts lineage within A and creates cross-tenant foreign-key/cascade coupling. B's asset data and status are not shown or changed in this reproduction. Similar single-column child foreign keys exist in forms/imports; those require separate verification before expanding the finding.

**Evidence:** `202606170001_phase_1_schema_rls.sql:229–241` asset-check FK is `asset_id -> assets(id)` without workspace; current contributor policy generated by `20260819174100_security_high_findings_remediation.sql:104–125` checks only the child workspace. `app/app/operations/actions.ts:881–897` accepts the submitted asset ID without a scoped parent lookup; lines 903–910 separately update only matching workspace and still report success after zero affected rows.

**Isolated reproduction:** Under Staff A's authenticated SQL role, SELECT of Asset B returns zero rows, but INSERT asset_checks(workspace_id=A,asset_id=B) persists one row. `audit-evidence/stage-1/vaeroex-core-rls-results.json`. Production FK and trigger definitions were confirmed by read-only catalog inspection: single-column asset FK and timestamp-only trigger; see production-asset-constraints.json.

**Correction:** Enforce composite workspace+parent foreign keys (or equivalent trusted constraint) and validate the parent under the active tenant before mutation. Keep any approved role-specific asset-status update transactional. Audit historical mismatches read-only first; no automatic historical-data deletion.

**Verification:** Foreign/missing asset IDs fail both direct Data API and server-action tests, no child row persists, and ordinary same-tenant Staff checks behave according to approved role policy. Cross-workspace parent deletion must not affect another tenant's rows.

### VXA-006 — Medium — User and workspace quotas are partitioned by source IP

**Impact:** A user/workspace can obtain another full AI quota by changing source IP. Consequently configured user/workspace limits are per-user-per-IP/per-workspace-per-IP, undermining aggregate abuse/cost protection. Claimed forwarding headers can worsen this if not stripped by the hosting edge; that part is a credible concern, not verified production behavior.

**Evidence:** `lib/security/rate-limit.ts:71–81` always appends IP to every identifier before hashing, including authenticated identifiers. `lib/ai/provider-guardrails.ts:25–42` calls this as `ai.provider.user` and `ai.provider.workspace` (defaults 60/240 per 600 seconds). `clientIpFromHeaders` at 39–45 prefers `cf-connecting-ip` then `x-real-ip` over `x-forwarded-for`; no local trust-boundary logic verifies those headers. Actual atomic DB quota consumption itself is a positive control.

**Isolated reproduction:** `audit-evidence/stage-1/vaeroex-security-isolation.cjs` invokes the actual limiter twice with identical workspace/action and two synthetic source IPs; captured RPC arguments use two distinct identifier hashes. It also confirms a supplied `cf-connecting-ip` wins over forwarded address. Output `audit-evidence/stage-1/vaeroex-security-isolation-results.jsonl`. A live bypass volume test was not run.

**Correction:** Use separate aggregate keys for authenticated user and workspace quotas; add a separate network/IP quota based on a verified edge-provided address. Do not incorporate mutable IP in the aggregate account quota. Preserve atomic fail-closed quota consumption.
