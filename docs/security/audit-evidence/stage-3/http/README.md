# Isolated Vaeroex HTTP workload kit

This is a Stage 3 assessment harness, not an application change or a second finding ledger. The persistent ledger is `../../../workspace-audit.md`. **No 100/250/500-user Vaeroex workload has run.** No matched disposable Supabase/Auth/provider environment is available in this session. Missing adapters are blockers, never passing results. `selftest.mjs` tests this harness only.

## What is implemented

Node 22+ built-ins implement guarded HTTP, manifests, open-arrival scheduling, thresholds, evidence logs and inventory comparison. The optional provisioning tools load the selected source checkout's installed Supabase packages; form capture loads its installed Playwright. Nothing installs a package. All generated session/capture/key files must stay outside repository evidence, mode `0600`, in a `0700` directory. Never commit real session cookies, bearer tokens, cron/service keys, HARs, or captured bound action payloads. No password is written or printed.

- `generate.mjs` produces synthetic account/workspace plans and deliberately unready templates; it creates no accounts.
- `seed-local.mjs` really provisions synthetic local Auth accounts (confirmed email, no email sends), memberships, standard manual entitlement rows and small issue/SOP fixtures. It generates passwords in memory, uses the installed SSR client to produce correctly chunked cookies, and writes private sessions. It refuses preexisting workspace IDs/output files. Partial failure leaves a receipt; it does not erase or mutate existing accounts. Read-back validation still belongs to preflight and the independent exporter.
- `seed-corpus.mjs` really uploads local synthetic storage objects and inserts source/KPI rows/settings, then checks scoped row counts. It does not invent provider approvals, real import success, saved analyses or legal acceptance. Direct fixture seeding is not a test of upload/import actions.
- `capture-form.mjs` reads a real authenticated form and submits only to Playwright's interception layer. Every POST is captured then aborted **before dispatch**. It captures actual hidden/bound Server Action metadata; it does not invent API endpoints/action IDs. Output is `ready:false`, requires synthetic correlation placeholders, explicit success/rejection acknowledgement contract and same-build/actor qualification. Dialog forms must be opened in the page or addressed by a selector that finds the rendered form; capture may require a small local UI adapter for the selected source version. This does not claim all UI controls were exercised.
- `run.mjs` refuses missing telemetry/fixtures/adapters/session/commit provenance. `smoke` uses five synthetic owner actors for 60 seconds; `baseline` uses the quiet tenant subset at the same per-actor action rate/mix for 20 minutes; `run` is the primary 25-minute stage. `soak` adds two-minute ramp, 60-minute steady state and three-minute drain for 100/250 actors; 500 actors would exceed the 100,000-request bound and is explicitly refused rather than silently shortened.
- `verify-inventory.mjs` is an offline comparator for independent, complete normalized before/after exports. It never infers persistence from a toast, 200 or redirect. Database/storage/job/citation/actor-readback exporters remain required adapters, with completeness explicitly checked.

## Safety and environment contract

Every harness HTTP request is limited to literal `http://127.0.0.1:PORT` or `http://[::1]:PORT`; no DNS names, URL credentials, external redirects, known live/preview Supabase project references or Vaeroex hosts. Redirects are inspected but never followed. Application and Auth origins are separately fixed. Capture blocks service workers, external requests and unsupported HTTP methods. SDK provisioning fetches allow only the declared local Auth/storage origin and use `redirect:error`.

**Loopback is not proof that a local app is safe.** Before setting `environment.ready=true`, an operator must prove the app, DB, Auth, Storage, workers and stubs are disposable, bound to this run, synthetic-only, and network-isolated. A local app forwarding requests to production is forbidden. The harness requires a same-run network evidence file with `egressDenyAllExternal:true`, `syntheticOnly:true`, `paidCredentialsPresent:false`; provider calls must resolve to local stubs. No real OAuth authorization/refresh, Square/Google/QBO/Stripe calls, email delivery, model calls, or production DB access are permitted. Egress isolation applies to the entire application/service network, not merely this client. The file is operator/collector evidence, not cryptographic proof generated by this harness; record the firewall/network-namespace commands and observed deny checks independently. Do not satisfy this preflight with a mock app or fabricated collector values.

Environment requires matching source commit, at least five source-file SHA256 checks (include app route/actions, schema inputs, provider transport and build identity), production build mode, fresh provisioning timestamp, schema fingerprint, instance nonce, local origins, telemetry path and inventory paths. Telemetry must independently identify the running PID/build/nonce and DB schema; matching files alone do not establish the running process uses them. Missing provider endpoint injection in the chosen source is **blocked** until an isolated transport fixture or network-local proxy is qualified; do not edit production provider endpoints or copy paid credentials to make this kit run.

Hard stops cancel all in-flight client fetches through one AbortController and stop new issuance. Final client wait is bounded to five seconds. HTTP cancellation does **not** guarantee a server-side mutation/job stops; the isolated operator must independently stop worker intake and reconcile active jobs, while preserving the instance for inspection. The kit does not kill arbitrary user processes or run production cancellation commands.

## Workload and corpus

| Active actors | Workspaces | Registered users | Per-actor actions/min | Steady user actions/sec |
|---:|---:|---:|---:|---:|
| 100 | 20 | 200 | 6 average | 10 |
| 250 | 50 | 500 | 6 average | 25 |
| 500 | 100 | 1,000 | 6 average | 50 |

Five active users per workspace, ten registered users. Owner-only manual sync is attributed to the owner of the selected workspace; the *cohort average* is six actions/min, and per-actor distribution is reported rather than falsely claimed equal. Remaining roles stay seeded for follow-up denied-permission tests; this capacity mix does not replace Stage 1's full role matrix.

The fixed mix is 30% document navigation, 20% authenticated deterministic search, 20% source filters, 8% CSV upload, 8% issue creation, 4% repeat submission, 5% stubbed conversation and 5% owner manual sync. Repeat is one user action/two HTTP requests with the same logical ID. Jobs and preflight requests are additional HTTP requests; target actions/sec is not mislabeled requests/sec or literal simultaneous sockets. HTML GETs do not load every browser asset, run hydration, or reproduce client CPU. Browser sampling remains separate.

Primary profile: two-minute linear ramp, twenty-minute steady state, three-minute drain; no arrivals during drain. Scheduled Sheets ticks at primary seconds 0 and 900 each select all eligible seeded connections. Manual calls overlap those ticks. The scheduler's own limits/claim semantics remain under test; the harness must not issue one fake scheduler tick per workspace to hide backlog. Uploads rotate 80% approximately 40 KiB, 15% approximately 0.4 MiB and 5% approximately 2.1 MiB valid synthetic CSV. Row-aligned padding may exceed these targets by one short row. Every file stays below 25 MiB. A 25 MiB boundary upload is a **separate bounded case**, not part of this primary load and not executed by this kit.

Normal corpus per workspace: 200 active original files; 10,000 KPI observations across 20 explicitly confirmed synthetic metric definitions and 730 days relative to `plan.asOf` (approximately 24 months). Seed active CSV objects are approximately 40 KiB. Growth corpus: 500 active plus 1,500 archived sources, with archived objects approximately 1 KiB. Archived-file support and counting must be verified against the chosen plan; never label 2,000 active files as a normal supported account. The actual 500-active-file quota is retained. In growth mode uploads must use a qualified **quota-denied** response contract and expected inserted count zero; successful growth uploads at that cap require explicit investigation. A synthetic limit-override experiment would be a separately labeled scenario, not this normal workload.

Seeder `completed:true` describes its scope only. Full readiness requires provider fixtures, due automatic connections, local entity/mapping approvals, legal acceptance, stored analyses/representative evidence paths if measured, fresh telemetry and complete independent exports. The telemetry collector must verify corpus counts in **every** workspace, not average or total counts. Calendar behavior is evaluated against the fixed `asOf` fixture clock or explicitly reported stale-run date; do not silently use a stale old fixture as current data. No performance claim about realistic documents follows from 40 KiB seed objects alone.

Client request budget is 100,000 per primary or soak run including Auth/app preflight, repeated HTTP actions and scheduled requests. Writes since provisioning must remain at or below 8 GiB; collector reports `storageBytesWritten` across seeding plus workload. The active/archived size distinction fits that bound without claiming all historical objects have the larger upload mix. No automatic cleanup; the operator destroys only the identified disposable environment after preserving sanitized evidence.

## Prepare and run (not executed here)

Use a new private absolute output directory for each run. The examples use a task-specific runtime variable; all manifests containing secrets remain outside this repo.

```sh
AUDIT_NODE=/absolute/path/to/node
AUDIT_HTTP=/absolute/path/to/docs/security/audit-evidence/stage-3/http
"$AUDIT_NODE" "$AUDIT_HTTP/generate.mjs" 100 /private/tmp/vaeroex-capacity-100 nominal
# Independently create local production build + matching Supabase migrations/storage + network isolation.
# Complete environment.json from template and private-keys.json: runId, local serviceKey, anonKey, cronSecret.
"$AUDIT_NODE" "$AUDIT_HTTP/seed-local.mjs" PLAN ENV PRIVATE_KEYS ISOLATED_PACKAGE_ROOT PRIVATE_SESSIONS
"$AUDIT_NODE" "$AUDIT_HTTP/seed-corpus.mjs" PLAN ENV PRIVATE_KEYS ISOLATED_PACKAGE_ROOT CORPUS_RECEIPT
# Complete legal consent/provider approval/stub/collector/exporter adapters; capture one form per necessary actor/binding.
"$AUDIT_NODE" "$AUDIT_HTTP/capture-form.mjs" PLAN ENV SESSIONS ACTOR_ID create 'form:has(input[name="title"])' ISOLATED_PACKAGE_ROOT PRIVATE_CAPTURE
# Captures remain unqualified until ack + persistence checks are independently proven.
"$AUDIT_NODE" "$AUDIT_HTTP/run.mjs" smoke PLAN ENV SESSIONS ADAPTERS NEW_SMOKE_DIR
"$AUDIT_NODE" "$AUDIT_HTTP/run.mjs" baseline PLAN ENV SESSIONS ADAPTERS NEW_BASELINE_DIR
# Take independent complete baseline inventory after setup/smoke/baseline mutations; point ENV to baseline summary/inventory.
"$AUDIT_NODE" "$AUDIT_HTTP/run.mjs" run PLAN ENV SESSIONS ADAPTERS NEW_RUN_DIR
# Export final DB/storage/jobs/citations and actor readbacks after drain/reconciliation.
"$AUDIT_NODE" "$AUDIT_HTTP/verify-inventory.mjs" PLAN BEFORE AFTER ACTIONS_JSONL REQUESTS_JSONL NEW_INTEGRITY_RESULT
```

To run the separate unexecuted soak after primary acceptance, use `run.mjs soak` with the same argument order and a new output directory. Sessions must remain valid for the entire 65-minute window or the preflight refuses; token rotation/refresh is not simulated by extending a local TTL and remains a separate untested lifecycle requirement.

Repeat with 250 then 500 only if prior scale smoke/run/integrity and stop review permit. Missing dependencies mean **blocked**, not grounds to substitute a fake server. `seed-local` uses local packages matching the target; it does not purchase/provision services. The Supabase Auth Admin `createUser` and SSR cookie APIs were checked against installed types/source and official [createUser documentation](https://supabase.com/docs/reference/javascript/auth-admin-createuser) and [SSR advanced guide](https://supabase.com/docs/guides/auth/server-side/advanced-guide). The skill's changelog endpoint could not be rendered by the browsing tool; no package upgrade was performed.

## Adapter and telemetry formats

`adapters.json` is private, runId/sourceCommit/instanceNonce bound. Each mutation has `ready:true` only after qualification, the same sourceCommit/nonce, and an `ack` object: `statuses:[303]`, plus either decoded `location:{pathname,query}`, a JSON scalar matcher `json:{...}`, or a unique `includes` marker. Status alone cannot pass. Native Server Actions contain per-actor `actorId`, `captureWasAbortedBeforeDispatch:true`, `path`, `encoding:"multipart"`, `headers` restricted to Next-Action/Next-Router-State-Tree/Accept, and `entries:[{name,value}|{name,fileFixture:true}]`. Use `{{logicalId}}` in title/display_name and preserve captured bound metadata. `byActor` maps actor IDs to these qualified captures. Never transplant encrypted action metadata across builds/actors. Upload useActionState requires real capture; unbound legacy uploadFileAction is not a substitute for the visible UploadSourceForm.

Do not log or archive raw response bodies. Requests evidence records IDs, route, status, elapsed time, expected outcomes and correlation only. Form/server-action response acknowledgement remains separate from durable inventory verification. Default templates leave every mutation/job unready.

The collector atomically updates `telemetryFile` at least once per second; samples older than ten seconds abort. Minimum shape (placeholders are deliberately invalid):

```json
{
  "runId":"UUID", "observedAt":"ISO timestamp",
  "app":{"pid":123,"sourceCommit":"40hex","instanceNonce":"24+chars","buildMode":"production","rssBytes":1,"allocationBytes":1},
  "db":{"origin":"postgresql://127.0.0.1:54322","schemaFingerprint":"64hex","connections":0,"maxConnections":100},
  "fixtures":{"runId":"UUID","syntheticOnly":true,"registeredUsers":200,"workspaces":20,"activeFilesPerWorkspace":200,"archivedFilesPerWorkspace":0,"kpiObservationsPerWorkspace":10000,"historyMonths":24,"providerFixturesReady":false,"legalAcceptanceReady":false,"corpus":[{"workspaceId":"UUID","activeFiles":200,"archivedFiles":0,"kpiObservations":10000,"confirmedMetricDefinitions":20,"historyDays":730,"verifiedStorageObjects":200}]},
  "egress":{"enforced":true,"violations":0}, "providers":{"mode":"local_stubs_only","paidCalls":0},
  "storageBytesWritten":0,
  "queue":{"depth":0,"oldestAgeMs":0,"oldestEligibleAt":null,"completed":[{"id":"stable-logical-job","eligibleAt":"original ISO eligible/enqueue time","startedAt":"actual execution ISO time"}]},
  "integrity":{"violations":[]}
}
```

`oldestEligibleAt` is the original eligible/enqueue time, not current scheduler tick, retry creation or lease reacquisition. Completed queue observations use stable logical job IDs, original eligibleAt and actual startedAt; the harness deduplicates by ID and retains the greatest observed wait. Repeated collector snapshots do not multiply samples. Claims of fairness use **per-page-route** p95 comparisons with at least 30 accepted observations per route/quiet workspace in both runs. Baseline and primary quiet actors use the same action mix/rate; global jobs/noisy neighbor load are the intended comparison difference. Low sample count means no fairness pass. Overall pooled read p95 is not a substitute.

The verifier indexes logical mutations and storage relations instead of rescanning the full corpus per action. The parent does not parse inventories: it launches a child with a 768 MiB V8 heap limit and 120-second deadline. The combined before+after input cap is 256 MiB and the post-parse RSS ceiling is 1,280 MiB; memory exhaustion/timeout returns BLOCKED without qualification. Do not run that comparison during the measured app window. Large 500-cohort exports may exceed this bound and are explicitly BLOCKED pending a bounded sharded/streaming exporter; do not trim evidence to force a pass.

The normalized independent inventory must include same runId/sourceCommit/schemaFingerprint, `completeness` booleans for databaseRows/storageObjects/primaryMutationMapping/allRelations/citations/jobs/actorVisibility, and `requestReadbacksComplete:true`. Rows include table/id/workspaceId/contentHash/immutable/parents/primaryLogicalId/requiresStorage; objects include id/workspaceId/recordTable/recordId/sha256; jobs include id/workspaceId/effectKey/committed/accepted/status/originalEligibleAt/startedAt; citations include id/workspaceId/sourceWorkspaceId/resolved; observations include requestLogicalId/actorId/recordWorkspaceId/recordTable/recordId/visible and own_workspace/foreign_workspace probe identities; recordTable/recordId must identify a real exported fixture. jobDispatches maps each accepted manual/scheduled request logicalId to actual jobIds, including coverage of all eligible workspace jobs for each accepted scheduled tick. The exporter must read persisted data and verify actual original-object hashes, citation resolution and allowed/denied actor reads. Empty arrays plus asserted completeness are not valid evidence. Correlation maps every accepted create/upload/analysis to one primary record; repeat and uncertain acknowledgements must not produce duplicate logical effects. Jobs use logical idempotency identity distinct from physical attempt IDs. Explicit failures/cancellation are accounted outcomes, not silently lost jobs. Matching source/schema digest formats, baseline corpus counts per workspace, valid content hashes/job timestamps/effect IDs, per-request readbacks and own/foreign actor probes are mandatory. Missing adapters cause BLOCKED even when no violation has yet been observed.

## Acceptance and automatic stops

Requested targets: p95 reads ≤1,500 ms, p99 reads ≤3,000 ms; p95 acknowledged successful mutation ≤2,000 ms; unplanned failed requests ≤1%; integrity zero loss/duplicates/cross-workspace effects; p95 original queue delay ≤30 seconds; nominal backlog drain ≤120 seconds; fault recovery ≤300 seconds; each quiet-tenant/page p95 ≤2× its matched baseline.

Stop on app RSS >80% allocation continuously for 60 seconds; DB connections >80% limit for 60 seconds; unplanned error fraction >5% for 60 seconds (60-second rolling window, at least 20 observations); queue original oldest age >120 seconds for 60 seconds; any integrity/egress/paid-provider violation; stale telemetry; client request/storage budget exceeded. The reporter preserves planned-fault failure counts separately. The stop/acceptance unplanned-error denominator excludes qualified planned-fault failures; an additional all-request denominator is reported transparently. Response percentiles and failure thresholds use steady-state requests by initiation time, with all-phase pooled statistics reported separately. Fault recovery requires a positively observed matching injection and fresh collector `recovery:{healthy:true,faultKind}` plus an empty queue; zero configured/qualified faults yields null, never a recovery pass. It reports achieved steady actions/sec, dropped offered actions, distinct actors, action mix, and generator lag. Steady action-mix qualification requires each requested share within 5% of its expected count (or three actions for small samples); generation lag p99 must be at most 100 ms. Passing target-only numbers without achieved-load/coverage/integrity does not establish capacity. No safe supported-user ceiling is emitted automatically.

## Runnable chaos protocol and remaining external adapters

Use a separate reset/reseeded `scenario:"chaos"` environment. The HTTP schedule is runnable now; **the fault injector and telemetry/exporter must be supplied locally and qualified** before any chaos result. The harness does not invent provider failures or pretend to kill a worker. Define each bounded fault in ENV with kind (`worker_interruption`, `expired_authorization`, `provider_throttle`, `partial_read`, `commit_ack_loss`), startSecond, endSecond, affected actions, expected HTTP statuses/errorCodes and evidenceFile. The injector writes same-run kind/matching planned interval, localOnly:true and `observations:[{startedAt,endedAt,actualInjection:true}]`. A matching configuration string alone cannot exclude errors. Failed requests are planned only when actual injection evidence covers their start time and action/status match. All other errors remain unplanned. Resource/integrity hard stops apply even during faults.

Suggested sequence within the 20-minute steady window (no fault overlaps until independent recovery is demonstrated):

1. Seconds 240–255: interrupt only the identified local worker while accepted work is queued; restart the same disposable worker. Verify lease expiry/reclaim, original queue age and one logical effect.
2. Seconds 420–435: local Sheets stub returns expired authorization; verify explicit reauthorization-required outcome, no stale-success label and no provider traffic. Restore stub credentials locally, not production secrets.
3. Seconds 600–615: local stub returns 429 with bounded Retry-After; verify backoff, retained original eligibleAt, manual/scheduled lease overlap and no duplicate imports.
4. Seconds 780–795: local stub returns one successful page then transient read failure; verify checkpoint and partial-state visibility, retry covers missing page without duplicating the first.
5. Seconds 960–975: disposable DB/proxy commits a synthetic mutation and then drops the acknowledgement. Repeat the same logical event through the real action. Reconcile database and storage; expected one primary effect. Existing VXA-028 may correctly fail this requirement.
6. Use matched quiet-tenant traffic throughout and observe recovery after each fault. Every queued/accepted job must reach an explicit terminal outcome, and backlog must recover within 300 seconds. If a fault's recovery extends to the next planned fault, do not inject the next fault; record blocked coverage.

Fault-control commands must refer to exact locally provisioned PID/container/transport and be recorded by the operator. Missing or ambiguous identity blocks injection. This protocol adds no production operations, scheduled automation, purchase, migration or app modification. Session expiration, repeated clicks, ordinary quota denial, failure recovery and final persisted checks remain real workflow requirements, not satisfied by this README or harness selftests.
