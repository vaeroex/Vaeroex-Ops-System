## Evidence levels

- **Implemented** means code exists for the stated boundary, not merely a descriptor declaration.
- **Fixture-tested** means deterministic synthetic/local regression coverage; the combined PR's exact-head CI is the validation record.
- **End-to-end tested** requires a real, authorized isolated Square sandbox flow through OAuth, runtime and persistence. **No Square E2E evidence exists here.** Historical synthetic GCP verification is not Square E2E.
- **Activated** requires separately authorized registry, database, credential, runtime and operational gates. **Square is not activated or registered.** QBO's existing environment/database disabled gates remain unchanged; fixture results do not attest to current live environment settings.

The [descriptor](../../lib/integrations/providers/square/descriptor.ts) declares streams, backfill, concurrency two and a 500 ms default delay. These are contracts, not deployed synchronization or measured provider readiness. Its historical `response_domain_minimizers` unsupported label is not an up-to-date inventory of pure parsers; the implementation and tests below are the evidence. The descriptor/fingerprint is preserved.

## Reuse without changing QBO

Reuse generic contracts and interfaces: canonical/source/fact versions and exact serialization; fingerprint/decimal helpers; existing Square request validators and response-boundary patterns; read-only POST policy; credential broker/KMS/AAD/state/redaction; lease/checkpoint/CAS/task/OIDC planning; lifecycle/freshness and safe status components. Shared SQL authorization must still explicitly admit the future Square contract.

Do **not** reuse provider-specific QBO behavior as if it were generic:

- [QBO fetch transport](../../lib/integrations/provider-runtime/qbo/fetch-transport.ts) is GET-only and Intuit-specific; Square has allowed read-only POSTs.
- QBO OAuth/realm verification, callback handoff, revenue mapping, service execution, queues, IAM/deployment bindings and credentials remain QBO-owned.
- [Provider validation repository](../../lib/integrations/persistence/provider-validation-repository.ts) contains `read_qbo_sandbox_*` RPC calls despite its generic-looking name.
- Existing SQL provider/source/scope predicates and registry do not permit Square solely because a TypeScript schema accepts a provider key.
- In-memory worker/limiter fixtures are correctness models, not a deployable universal worker or cross-instance rate coordinator.

Keep canonical economic contributions gated until source authority/reconciliation is separately proven. Actual provider calls, OAuth, database registration, private runtime provisioning, UI and sandbox qualification require later explicit authorization.
