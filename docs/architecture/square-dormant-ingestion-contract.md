# Dormant Square ingestion and completeness contract

Baseline: `b4f08dc7f5f0f6e0ae61a03ff3bb139473e2a7fa`. API `2026-08-19`, SDK `45.1.0` at `e4a5bf7e1a2b97c2b995fde28c55ddbc35dc0e76`. This is a synthetic dependency-injected adapter, not an activated provider or durable database implementation.

## Shared boundary and repository reuse

`ingestion-contracts.ts` establishes the interfaces before component implementation. `ingestion-adapter.ts` connects an injected authority resolver, the bounded client, a freshly called existing parser, the pending mapper and an atomic page repository. It performs exactly one read/page per invocation and returns a bounded continuation/retry outcome. There is no default transport, token lookup, provider registration, scheduler, SQL write, source validation promotion or canonical fact generation.

Reused unchanged: Square request allowlists and read-only POST policies; all eight projection parsers, including the trusted Catalog facade; exact canonical hashing; generic `ExternalSourceRecordVersionSchema` and `prepareExternalSourceVersionCommit`; pending/untrusted source semantics. Generic lease/generation/CAS and freshness contracts informed the interface, but their RPCs are not invoked. Generic checkpoint cursor text is capped at 1,024 characters whereas existing Square parsers permit 4,096; the private synthetic cursor contract therefore preserves Square's 4,096-character bound instead of silently truncating it. QBO transport, realms, revenue mapping, source-validation RPCs and services are not generic dependencies.

## Trusted invocation and authentication lifetime

The public factory requires injected authority, transport and repository dependencies. An opaque invocation is resolved by a **trusted** dependency into a grant containing workspace, Business Entity, connection, seller, environment, authorized locations, generation, stream, operation, scan identity, cursor-free request and expiry. No helper creates authority from caller-supplied merchant/location IDs. Merchant/Location shape projections are not used as authentication. Fixtures resolve object-identity tokens and explicitly install model generation fences; this is not OAuth verification.

The adapter snapshots the grant without invoking Proxy traps or accessors, validates its fixed shape, checks the existing request policy, and derives parser request context from that exact authorized request. ListPayments without `location_id` requires an explicit resolver-supplied default location; the adapter never guesses the seller's main location. Literal cursor `+`/`=` bytes are preserved. It re-resolves the grant before committing. The repository must atomically fence the current scope/generation, lease and checkpoint version. A future durable authority implementation must coordinate revocation/generation changes with that fence; checking an earlier grant alone is insufficient.

Existing acceptance authentication is current-parser-invocation-local. Only the direct return value of the just-called parser enters mapping; callers cannot submit accepted results, and acceptance objects/tokens are neither stored nor replayed. Pending envelopes are deliberately untrusted external input, not persisted parser authentication. Orders' older cursor contract is checked against its unchanged response fingerprint plus full query/scope/generation checkpoint custody. The newer parsers independently verify request and response cursor bindings.

## Identity, versions and ordering

| Concept | Contract |
| --- | --- |
| Resource identity | Hash of workspace, Business Entity, connection, seller, environment, projection stream, record type/role and natural provider identity. Excludes observation time, request, pagination and generation. |
| Natural identity | Order ID per projection scope; Payment/Refund ID; Catalog ID plus primary/related/included role and type; Inventory change ID or existing count snapshot composite identity. Missing required mapping identity blocks the entire page. |
| Immutable observed version | Hash of resource identity, mapper version, exact intrinsic minimized content, provider revision and deletion flag. Same content from another page, scan, observation time or authorized generation identifies the same version. |
| Generic envelope | Pending, `untrusted_external_input`, exact minimized projection; deterministic version UUID. Repository allocates an immutable arrival ordinal and prior observed version ID atomically. Natural IDs remain in the minimized projection; the generic 128-character identifier slot uses the scoped identity digest without truncation. |
| Observation time | First successful delivery's observation time is retained on version-key deduplication. It is not a provider update clock or proof of recency. Generic source fingerprints include this retained time; version-key deduplication happens before materialization. |
| Provider ordering | Numeric Order/Catalog versions are compared exactly. Otherwise a supported modification/snapshot timestamp is compared at its exact fractional precision and offset. Inventory event creation/occurrence times are not modification clocks. Missing/incomparable revisions are unordered. |
| Equal revisions / late changes | Different content at the same provider revision is a conflict. Older, unordered and conflicted observations are retained immutably but do not replace the model's current pointer. Arrival ordinals never imply provider chronology or economic authority. |
| Deletion | Explicit Catalog tombstones persist as deleted versions with null projection and retained identity/revision. Missing objects or completed scans never imply deletion. |

Order core, line-item, adjustment and Tender scopes remain separate, even where richer projections contain earlier scopes. Tender Payment references, Payment refunded aggregates, Refund references and Inventory legacy references remain unresolved. Catalog children stay nested; related/included objects get separate non-authoritative record types. Nothing resolves cross-stream identities or generates contributions, sales, revenue, settlement, stock movement, valuation or reconciliation.

## Completeness and unsupported data

Every mapped page reports `historical: unknown` and `economic: blocked`, regardless of whether its cursor sequence finished. Reasons explicitly include omitted economic fields, unresolved references, eventual consistency and overlapping representations. Orders always carry `returns_unknown`, because the existing minimizer discards return fields; their absence cannot prove there were no returns. No new raw return signal or fingerprint change was introduced.

Inventory is optional and does not establish stock truth. Known `UNTRACKED` values remain provider observations. `SUPPORTED_BY_NEWER_VERSION`, including adjustment-group states, blocks mapping as unsupported. Parser-unsupported variants or a mapped record lacking stable identity block the **whole page**, with zero source commits and no checkpoint advancement; supported neighbors are not silently treated as a complete page. Malformed/foreign envelopes also cannot advance a checkpoint. Interruption, expiry, exhaustion and capacity limits retain incomplete state. Completing one scan is not a history-completeness or freshness transition, and the adapter does not call the existing freshness lifecycle to mark a connection Current.

Overlapping windows are exact request-bound independent scans that deduplicate source versions. This milestone does not choose a commercial backfill horizon, guarantee historical coverage, infer deletions from gaps, or establish measured consistency/freshness thresholds.

## Bounded client and resource derivation

The client reuses exact methods, hosts, paths, query/body policies, API-version headers, manual redirect policy and allowed read-only POST exceptions. Transport is injected and receives only the literal synthetic fixture credential. Redirect responses are rejected before any follow-up request; a changed response destination is rejected. One overall 30-second deadline covers open, body and cleanup; cancellation propagates an AbortSignal, late-open responses are cancelled, and hanging asynchronous dependencies cannot extend the caller's wait. A deliberately synchronous infinite loop in an injected trusted dependency is outside JavaScript's preemption capability.

The 16/64 MiB existing operation byte caps count streamed bytes without trusting Content-Length. A 64 KiB staging buffer bounds retained text blocks to 1,024 plus a tail, even for one-byte chunks. Fatal UTF-8 decoding rejects malformed bytes. Decoded UTF-16 text and its join each use at most twice the byte cap; the parser creates at most 20,000 raw values. JSON parsing itself enforces depth 12, arrays 1,000, properties 64, keys 128 and strings 4,096 before any downstream schema/fingerprint traversal. Duplicate/pollution keys are rejected. Numeric lexemes are normalized into a bounded decimal coefficient and scale before Number conversion, then must match the exact decimal normalization of Number.toString(). This accepts ordinary fractional coordinates, including 0.1 and 37.123456, without silently collapsing extra decimal digits such as 1.0000000000000001. Magnitudes above Number.MAX_SAFE_INTEGER, non-finite values, underflow and negative zero reject. At most 17 significant digits and a short scientific token are retained; no unbounded BigInt conversion is used. Numeric quantities remain numbers and are still rejected by quantity-string schemas; fractional Money remains rejected by the existing integer contract. No parser type is repaired or weakened.

Failures are fixed payload-free codes: authorization, rate limit, transient, malformed response, provider error, redirect/destination denial, oversized body, deadline/cancellation and invalid request. No response body, provider error detail, cursor or credential is logged. Client attempts 1–3 perform one request each; only attempts 1–2 may receive a retry plan, with 500/1,000 ms baseline and a maximum 60-second delay. A valid Retry-After beyond the permitted delay produces no automatic retry rather than an earlier clamped retry. Separately, the adapter's outer deadline returns a 30-second retry delay, allowing the bounded lease lifetime to elapse even when acquisition started after invocation entry. It does not release a potentially committing page after an uncertain timeout. There is no retry loop.

The mapper traverses one accepted projection, never replicates whole responses per source, and never flattens child graphs. Proven existing accepted-container caps are Order 60,000, Catalog 23,341, Inventory 19,007, Payment 20,295 and Refund 20,195. Root source cardinalities are at most 1,000 Orders/Inventory records, 100 Payments/Refunds or 3,000 Catalog primary/related/included objects. Each source adds at most five containers; the mapped page adds four. Thus `C(mapped) <= max(C(parser)+5N+4) = 65,004`, with Catalog at most 38,345. Expanded shared occurrences count repeatedly, not once per identity. Fixed 32-level parser depth plus wrappers remains within the mapper's 38-level guard. The old projection arrays contain objects except Catalog availability/location arrays, whose scalar occurrences are copied once from the at-most-20,000-value raw tree. A deliberately over-combined value bound is therefore 65 × 60,000 old container/property values + 20,000 Catalog array scalars + 1,024 × 3,000 source-wrapper/location values + 10,000 fixed command allowances = 7,002,000, below the repository's 7.2 million expanded-value guard. The 1,024 per-source allowance covers its at-most-1,000 authorized locations and 24 wrapper/container/scalar values. Mixing the largest parser cap with Catalog's largest root count is conservative; a single invocation uses only one projection scope. Rejection precedes canonicalization.

The deterministic repository model has explicit capacity limits, not a claim to support arbitrary history in memory: 32 scans, 100 pages/scan, 10,000 immutable source versions, 3,000 sources/page, 64 MiB retained logical serialized bytes and 500,000 retained containers. Commands are preflighted at 64 MiB, 66,000 containers and 7.2 million values before hashing/materialization, including repeated references. Both pending and materialized versions count toward retained capacity. Staging temporarily retains old and candidate state; no unbounded history copy, eviction or forgotten replay receipt occurs. A capacity failure rejects the whole atomic commit and leaves the checkpoint/sources unchanged. These bounds do not modify the existing parsers or their accepted limits. A durable implementation needs its own reviewed bounded storage/transaction strategy.

Grant inspection is bounded independently at 5,000 values/depth 8/2 MiB aggregate text; its actual fixed schema has fewer than 1,020 values plus bounded request text. Public outcomes contain fixed codes, counts and bounded completeness reasons, never raw payloads or cursors. Per invocation there is one decoded response, one parser result, one mapped page and one atomic commit; no accumulating worker loop exists. Streaming waits retain only one active cancellation callback, cleared by identity on settlement or stop. They do not attach per-chunk reactions to a shared pending cancellation promise. Pending-wait regression instrumentation covers empty and one-byte chunks independently of heap/GC timing; late I/O rejection remains observed and contained. Each decoded string collects at most 4,097 transient UTF-16 character slots (including the first rejected value) and joins once, avoiding retained per-character concatenation chains. A separate capped-heap regression holds 1,000 maximum-length strings across explicit GC and checks a conservative retention allowance. Byte, raw-value and schema limits are unchanged.

## Page recovery and limits of the evidence

Scan identity binds tenant/connection/stream/scan ID, while immutable binding separately includes full cursor-free request identity, resolved-default location, scope, generation and existing cursor binding. Reusing a scan ID with another query or scope conflicts. Private cursors expire after at most one hour and never outlive the grant. Checkpoint advancement is permitted only in the same atomic transaction as source-version deduplication/materialization. A repeated cursor cannot create an endless page loop; page/attempt/capacity limits also stop continuation. Commit/restart outcomes return the repository's cumulative completeness, actual continuation eligibility and deferred retry delay, not merely page-local mapping state.

The synthetic repository requires a current generation to be explicitly installed. It verifies lease identity/expiry, checkpoint CAS, source scope/generation, binding and replay command identity. It stages all records and checkpoint state, then publishes one state pointer. Tests inject failures before staging, during staging and after publication (lost acknowledgement). Before/during faults leave no records or advanced cursor. After-commit retry observes the committed checkpoint; duplicates do not create another source version. Reconstructing the adapter over the same injected repository exercises restart/replay, not operating-system or database crash recovery. Stale leases/generations and cursor/query swaps fail closed.

A real database implementation must supply durable transaction isolation, generation/revocation fencing, uniqueness, immutable-version allocation, private cursor protection/retention and idempotent receipt lookup together. The existing Square-rejecting registry/SQL allowlists remain intact. The in-memory model is neither distributed exactly-once execution nor production write authorization.

## Evidence and remaining work

Four registered suites cover client/decoder/errors, mapping/bounds/completeness, repository recovery and the combined flow. The combined flow uses all 25 operation/projection combinations, existing parsers and generic pending serialization, with private cursor restart, duplicate/corrected/late observations, explicit tombstones, unsupported/mixed pages, cross-scope/generation rejection, cancellation and sensitive canaries. Existing parser/descriptor/request goldens run unchanged alongside these suites.

Required delivery gates are the exact-head repository CI (`verify`, `security-database`) and automatic Vercel Preview check. Preview success only establishes an application build, not Square E2E. Production remains dormant. See [production readiness](square-production-readiness.md) for the next explicitly gated milestone and durable/runtime dependencies.
