## Composition

- `square-gcp-mapped-contracts`: explicit Sandbox host, current connection/generation, actor session,
  default location, retention approval and separate role/secret references. Consent provider calls
  must be disabled. Mapped provider calls have a separate gate.
- `square-gcp-mapped-database`: fixed native RPC adapters with actual broker/enroller/runtime
  `session_user`; no SET ROLE, arbitrary SQL, service-role or Owner fallback. Pre/post-operation
  binding checks remain in the transaction; uncertain acknowledgements close the handle.
- Portal optional `mappedBinding`: authenticated CSRF-protected one-location confirmation through
  the existing mapping service. It does not enroll or fetch credentials. `--check-binding` verifies
  both bindings when mapped mode is configured.
- `enrollNativeSquareGcpMappedConnection` and `enrollNativeSquareGcpMappedTask`: explicit separate
  enroller LOGIN composition, using existing checked OAuth enrollment and task APIs. The currently
  valid operator session must match the mapping session. No synthetic enrollment gate is reused.
- `runNativeSquareGcpMappedPage`: one existing checked adapter invocation and one page, with actual
  runtime authority, broker credential resolution, task/page lease checks and atomic pending-page
  persistence. No scheduler, implicit retry, refresh, OAuth, webhook or economic activation.
- `square-gcp-mapped-credentials`: one task-bound native KMS decrypt, current authority checked
  around authenticated I/O. Application-secret access and encryption are absent. Native secret
  bootstrap reads only the exact role's pinned version; callback broker keeps its existing version.

Provider response limits, private 4,096-character cursor, exact Money/quantity parsing, source/version
identity, cumulative completeness and lease/generation/CAS fences are reused. A completed empty page
is evidence of that query only, not history completeness or economic authority.

The installed entrypoint supports four fixed noninteractive commands with
`--config /etc/vaeroex-square-callback/config.json`: `--confirm-mapping`, `--enroll-mapped`, `--enroll-task`,
and `--run-page`. The latter two read only the root-owned, non-symlink
`/etc/vaeroex-square-callback/mapped-task.json`; page execution accepts exactly `taskId`
and `leaseOwnerFingerprint`. These commands reuse startup/host checks, open no HTTP listener,
emit finite sanitized outcome labels, and have a hard deadline of at most 60 seconds.
They cannot extend the host or mapped approval window.
