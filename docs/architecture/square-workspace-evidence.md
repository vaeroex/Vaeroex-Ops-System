# Read-only Square Sandbox workspace evidence

The authenticated Vaeroex workspace Settings experience renders `SquareEvidenceCard` only after a successful checked read. It is not an activation of the dormant Square customer routes or registry. Production's different Supabase target fails the negative deployment gate before any RPC. The exact Sandbox application URL and database URL are required; the known Production Vercel project is denied.

The card derives counts from retained canonical facts, never hardcodes the hosted fixture totals. Qualification baseline: 1 Payment, 1 Refund, 3 Orders, 2 Catalog variations, 6 Inventory observations; 2 location-unresolved relationships and 1 conflicting reference. ID matches do not establish financial reconciliation. Historical completeness and current sync health remain explicitly unknown. Observation time is not successful-sync time.

## Authority and privacy

Additive migration 113 provides a narrowly minimized authenticated reader. A SQL-standard, pre-parsed invoker wrapper resolves one private definer function without granting private schema usage. Its elevated read is necessary because raw tables must remain inaccessible; it performs no writes and grants no source, broker, enrollment or interpretation capability. An actual disposable PostgreSQL test verifies that authenticated can call only the checked reader while direct table/schema access remains denied.

It checks verified JWT issuer/subject/session, current session existence/expiry, active membership (owner/admin/manager), user deletion/ban, active entity, exact Sandbox application, current connection/generation, seller, OAuth evidence, enrollment, revocation, retention policy and capacity/configuration fences. Multiple candidate connections fail closed. The selected partition is the distinct resource set already admitted for that connection/generation, not arbitrary latest or a sum of overlapping partitions. Every manifest member passes the existing immutable source/current-version/location validator and matches retained admission and interpretation facts. Expired write approval is not reused as a read credential.

Only bounded counts, uncertainty categories, checkpoint revision/times and per-resource source-version ordinals/times enter the UI. No workspace/entity/connection/seller/location/provider/source IDs, fingerprints, credentials, private cursors, source payloads, amounts or quantities are returned. Full immutable provenance stays private. Errors have one fixed outcome and no logged database/provider payload. No shared cache, mutation button, polling, model import or AI dispatch is added. Unavailable/invalid results hide the card rather than show stale or fabricated counts.

## Delivery and pending hosting

Migration 113 is committed for review only: **not applied remotely**. No configuration, deployment, credential, mapping, enrollment, consent, Production or QBO change is part of this milestone. Existing closed Sandbox gates continue to deny reads. The stopped GCP consent portal is a separate application: this PR targets the authenticated Vaeroex workspace Settings page, not its onboarding HTML. Hosted visibility requires deploying this workspace experience against the isolated Sandbox configuration and separately authorizing application of 113; it cannot appear in the Production workspace by copying Sandbox data or bypassing the database gate.
