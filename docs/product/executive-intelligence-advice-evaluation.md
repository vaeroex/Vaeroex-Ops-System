# Executive Intelligence advice: focused evaluation

Scope: the deterministic next step for KPI target misses, the fixed Explain Finding package and output check, and Business Health executive-analysis input and output check. Synthetic fixtures use the two customer-reported KPI values; no customer records or provider credentials are included. Baseline is merged main `271146e8`.

## Cause and evidence path

`/app/intelligence` loads workspace-scoped, parent-eligible KPI rows and builds findings in `lib/intelligence/layer.ts`. A material target miss previously received the same hard-coded next step regardless of metric. Explain Finding then copied that next step into `approvedInvestigationNext`, selected at most eight eligible supporting records for its citation manifest, and prohibited the model from inventing a different recommendation. Business Health selected its weighted drivers and citations, but its model payload contained driver facts without those approved next steps. Its four prose fields therefore had little distinct action to express. Both flows validate model output, attach application-owned citations, and save completed artifacts under the workspace.

The change uses the already eligible KPI row and confirmed KPI semantics. It does not retrieve or quote unrelated review text or join separate findings. Where the KPI row contains a review-text field, the advice reports only that the row has text; it still asks for review-level records and a verified metric definition. The Health model now receives each selected driver's approved investigation. Existing artifacts without that optional field still parse, while the changed package fingerprint requests fresh analysis for new evidence and actions.

## Generalized advice follow-up (PR #468)

The two named examples above were improved in PR #467, but other categories still exposed fixed next-step templates. `lib/intelligence/layer.ts` supplied generic KPI risk/opportunity, customer, issue, import, and SOP actions; `lib/intelligence/operational-evidence.ts` supplied fixed actions for imported operational risks, opportunities, and anomalies. Explain Finding copied that action into `approved_investigation_next` and prohibited the model from moving beyond it. Business Health copied selected drivers' actions into `approved_next_investigation`. A prompt-only rewrite therefore could not repair unfamiliar findings.

The shared planner now runs after duplicate consolidation and before these actions enter either model package. It uses only the selected finding's eligible original records, period range, priority, freshness, confirmed KPI direction/unit, a bounded classifier of its configured definition, and fields actually present in source rows. The classifier selects generic calculation inputs (numerator/denominator, timestamps, count identities, or measurement rows); it does not pass free-form metric definitions as trusted instructions. For an aggregate it requests the detailed source rows needed to establish a cause. For row-level records it identifies the cited rows, uses available fields only as conditional comparisons, and requests missing detail. Existing operational source instructions, such as checking the oldest unresolved customer cases, remain in the action. A user-written issue fix remains authoritative. Actions fit the 420-character generated-explanation boundary without sentence truncation. Scores, evidence eligibility, citations, saved artifacts, permissions, and model policy are unchanged.

The evaluation command is `node scripts/executive-advice-general-evaluation.cjs --json`. The same synthetic fixture was run against merged main `5378f611` and the proposed code.
